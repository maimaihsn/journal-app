# Daily Journal — 詳細設計書：データ層

> 最終更新: 2026-05-21

---

## 1. 概要

すべてのデータはブラウザの `localStorage` に保存される。サーバー・DBは不要。  
メインデータと設定データの2つのキーを使用する。

| localStorage キー | 用途 |
|------------------|------|
| `daily-journal-v2` | アプリ本体データ（蓄積・日別） |
| `daily-journal-settings` | Discord Webhook URL などの設定 |

---

## 2. メインストアスキーマ（`daily-journal-v2`）

```typescript
type Store = {
  persistent: PersistentData;  // 日付に関係なく蓄積されるデータ
  daily: Record<DateString, DailyData>;  // 日付ごとのデータ
}

type DateString = string;  // "YYYY-MM-DD" 形式
```

### 2.1 蓄積データ（PersistentData）

日付をまたいで共有される。一度登録したら削除するまで保持。

```typescript
type PersistentData = {
  wantToDo: WantToDoItem[];  // やりたいこと
  wishlist:  PersistItem[];  // ほしいもの
  goals:     PersistItem[];  // 目標
}

type WantToDoItem = {
  text:    string;   // 内容
  addedAt: string;   // 登録日（YYYY-MM-DD）
  done:    boolean;  // 実行済みフラグ
}

type PersistItem = {
  text:    string;  // 内容
  addedAt: string;  // 登録日（YYYY-MM-DD）
}
```

### 2.2 日別データ（DailyData）

閲覧中の日付に紐づく。日付ナビで切り替えるとそれぞれ独立したデータが表示される。

```typescript
type DailyData = {
  todos:    TodoItem[];  // 今日のToDo
  didToday: string[];   // 今日やったこと
  journal:  string;     // ジャーナリング（自由テキスト）
}

type TodoItem = {
  text: string;   // ToDoの内容
  done: boolean;  // 完了フラグ
}
```

### 2.3 格納例

```json
{
  "persistent": {
    "wantToDo": [
      { "text": "京都旅行", "addedAt": "2026-05-10", "done": false },
      { "text": "ピアノを習う", "addedAt": "2026-05-15", "done": true }
    ],
    "wishlist": [
      { "text": "ワイヤレスイヤホン", "addedAt": "2026-05-18" }
    ],
    "goals": [
      { "text": "毎日30分読書", "addedAt": "2026-05-01" }
    ]
  },
  "daily": {
    "2026-05-21": {
      "todos": [
        { "text": "買い物", "done": true },
        { "text": "メール返信", "done": false }
      ],
      "didToday": ["ジム", "コード書いた"],
      "journal": "今日は天気が良かった。"
    }
  }
}
```

## 4. CRUD 操作

### 4.1 読み込み

| 関数 | 対象 | 処理 |
|------|------|------|
| `loadStore()` | ストア全体 | `localStorage.getItem` → JSON.parse。失敗時は空のデフォルト値を返す |
| `loadPersistent()` | 蓄積データ | `loadStore().persistent` + デフォルト値マージ + 旧フォーマット変換 |
| `loadDay(date)` | 日別データ | `loadStore().daily[date]` + デフォルト値マージ |
| `allDailyDates()` | 全日付リスト | `Object.keys(store.daily)` を降順ソートして返す |
| `loadSettings()` | 設定データ | `localStorage.getItem('daily-journal-settings')` → JSON.parse |

### 4.2 書き込み

| 関数 | 対象 | 処理 |
|------|------|------|
| `saveStore(store)` | ストア全体 | `localStorage.setItem` に JSON.stringify して保存 |
| `savePersistent(data)` | 蓄積データ | `loadStore()` → `.persistent` を更新 → `saveStore()` |
| `saveDay(date, data)` | 日別データ | `loadStore()` → `.daily[date]` を更新 → `saveStore()` |
| `saveSettings()` | 設定データ | `localStorage.setItem('daily-journal-settings', ...)` |

## 5. データマイグレーション

アプリのバージョンアップに伴い、ストレージフォーマットが変化した。  
起動時に `migrateV1()` → `migrateV2ToV2_1()` の順で自動実行される。

### 5.1 v1 → v2（`migrateV1`）

| 変更点 | v1 | v2 |
|--------|----|----|
| 構造 | `{ [date]: { wantToDo, wishlist, goals, todos, didToday, journal } }` | `{ persistent: {...}, daily: { [date]: {...} } }` |
| 蓄積データ | 日付ごとにコピーされていた | `persistent` として一元管理 |
| 蓄積の移行方針 | 最新日付の非空データを採用 | — |

```
localStorage: daily-journal-v1  →  daily-journal-v2  (旧キーは削除)
```

### 5.2 v2 → v2.1（`migrateV2ToV2_1`）

| 変更点 | v2 | v2.1 |
|--------|----|----|
| 蓄積アイテムの型 | `string[]` | `{text, addedAt}[]` |

登録日（`addedAt`）フィールドを追加するためにオブジェクト形式に移行。  
文字列の場合はマイグレーション日時の日付を `addedAt` として付与する。

### 5.3 v2.1 → 現在（wantToDo に `done` フラグ追加）

`WantToDoItem` に `done: boolean` フィールドを追加。  
`loadPersistent()` 内で `done` が未定義の既存アイテムは `false` として扱う（暗黙的互換）。

---

## 6. データの整合性・制約

| 項目 | 内容 |
|------|------|
| 最大容量 | ブラウザの localStorage 上限（通常 5MB）に依存 |
| 日付形式 | `YYYY-MM-DD`（ISO 8601 の日付部分） |
| 文字列長 | Discord まとめ送信時のみ field あたり 1024 文字で切り捨て |
| バリデーション | 空文字・空白のみの入力は追加不可（`trim()` 後に長さチェック） |
| エラー処理 | JSON.parse 失敗時はデフォルト値を返す（データ破損に対して堅牢） |
